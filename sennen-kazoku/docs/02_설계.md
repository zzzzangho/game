# 02. 설계

## 기술 선택
- **Unity 6000.3 LTS** (`ProjectVersion.txt`에 명시), 2D/UGUI, C#. 세로 고정, Android 우선(IL2CPP/ARM64, minSdk 24). iOS 확장을 막는 플랫폼 코드는 없다(`UnityEngine.Networking`, `persistentDataPath`, UGUI만 사용).
- **코어/표현 분리**: `Assets/Scripts/Core`(asmdef `noEngineReferences`)에 규칙·이벤트·저장·콘텐츠 로딩·레이아웃 계산을 모두 넣었다. 덕분에 Unity 없이 `dotnet`으로 같은 소스를 컴파일해 테스트한다. `Assets/Scripts/Game`은 입력/그리기만 담당.
- UI는 씬 파일 없이 런타임 코드로 구성(`Bootstrap`). 편집기에서 열려도 빈 씬 하나만 있으면 동작한다. 한글 폰트는 OS 폰트 임시 사용(출시 전 라이선스 확인된 폰트 번들 필요).

## 원작 규칙 구현 방식
원작의 핵심 루프는 공략 데이터에서 확인된 **"인물마다 예정 상태 → 때가 되면 결과 이벤트 하나 선택 → 효과 적용 → 다음 예정 상태"** 이다.
- `PlannedStateDef`(상태, 대상 조건 `eligible`, 결과 이벤트 id를 표 순서로 나열) + `EventDef(kind=outcome)`(선택 조건 `trigger.condition`, 효과).
- 선택은 표 순서대로 조건(난수 포함)을 평가해 **처음 통과한 것 하나**(확인된 규칙). 마지막 결과는 보통 `always` 폴백.
- 조건 언어: `and/or/not/cmp/chance/has_skill/flag/has_role/always`, 수식 `add/sub/mul/div`, 변수 `self|spouse|father|mother.{age,int,stamina,charm,luck,hearts,immersion,job,mastery,gender,married}`, `family.{mood,mood_level,assets,house}`, `date.{year,month,day}`.
- 원작 규칙 팩은 `tools/import_original_pack.py`가 공략 데이터에서 **완전히 모델링되는 상태만** 생성한다(나머지는 건너뜀 + 사유 보고).
- 원작이 아닌 부분(날짜 단위, 상태 배정, 빈도 등)은 코드에서 "임시"로 주석 처리했고 화면 배지에도 `규칙 확인됨/추정/임시`, `원작 문구/임시 문구`를 표시한다.

## 이벤트 데이터 형식 (팩 JSON, `format: 1`)
```jsonc
{ "format":1, "packId":"nova.pack001", "version":1, "title":"…", "kind":"expansion",
  "origin":"new", "minContract":1, "requires":[{"packId":"sk.sample","minVersion":1}],
  "events":[{
    "id":"nova.picnic.001", "version":1,
    "origin":"new|original", "certainty":"confirmed|estimated|placeholder", "textSource":"original-translation|placeholder|new",
    "sourceRef":"sk-event-0001",            // 원작 이벤트 연결(있으면)
    "kind":"standalone|outcome", "title":"…", "category":"…",
    "roles":{"spouse":"spouse"},            // self 는 자동. 추가 역할: spouse/father/mother
    "trigger":{"condition":{…}, "weight":10, "priority":1, "cooldownDays":720, "maxPerPerson":0, "maxPerFamily":0},
    "pages":[{"speaker":"self","text":"{self:이가} 말했다."}],   // {역할}, {역할:은는|이가|을를|과와|으로}
    "choices":[{"id":"go","text":"…","condition":{…},"effects":[…],"result":[pages]}],
    "effects":[{"op":"family_mood","value":12}] }],
  "plannedStates":[{"id":"…","title":"…","minAge":18,"maxAge":29,"weight":10,"delay":[20,60],"eligible":{…},"outcomes":["이벤트id",…]}] }
```
효과 op: `add_stat/add_hearts/add_immersion/add_job_mastery/set_job/add_skill/remove_skill/family_mood/family_assets/set_flag/clear_flag/set_planned_state/log`.
- 같은 id의 이벤트에 `version`을 올려 개정한다. 이벤트 id는 전역 유일(충돌하면 팩 거부).
- **데이터 vs 앱 업데이트 경계**: 위 목록 안의 조건·효과·변수로 표현되는 내용은 팩(데이터)으로, 새 op/변수/시스템은 앱 업데이트 + `Capabilities.Contract` 증가. 팩의 `minContract`가 앱보다 높거나 미지원 op를 쓰면 검증에서 "앱 업데이트 필요"로 거부된다.

## 콘텐츠 배포·검증·롤백
1. `index.json`(`packId, version, url, sha256`)을 받아 새 버전만 다운로드(`ContentUpdater`, 서버 URL 미설정 시 오프라인 전용).
2. `PackStore.Install`: **sha256 → 단독 검증 → 현재 활성 집합과 교차 검증(id 충돌·의존성·참조)** 을 전부 통과해야 파일을 쓰고 `active.json`을 임시 파일 교체 방식으로 갱신.
3. 시작 시 `LoadCatalog`: 손상/충돌이 있으면 같은 팩의 이전 설치 버전 → 번들 버전 순으로 되돌아가고 경고를 보고. 설치된 파일은 로컬에 있으므로 오프라인에서도 사용.

## 저장 구조
- `save_{auto,slot1,slot2,slot3}.json`: `{schema, savedAt, packs{id:version}, family{…}}`. 임시 파일에 쓴 뒤 교체, 직전 정상본은 `.bak`.
- `SaveMigrator`: `schema`를 `from→from+1` 변환 체인으로 올림. 더 새로운 schema는 "앱 업데이트" 오류. 주 파일 손상 시 `.bak` 복원.
- **진행 중 이벤트는 정의 전체의 스냅샷(`snapshot`)을 저장**하므로 팩 업데이트로 이벤트가 바뀌거나 삭제돼도 끝까지 진행된다. 기록(`history`)은 id·버전·제목을 저장해 이후 콘텐츠가 사라져도 표시 가능.
- 현재 `CurrentSchema = 1`. 마이그레이션 메커니즘은 합성 v0→v1→v2 시나리오로 검증했다.

## 화면 설계
상단(날짜·무드·자산) / 가족 띠(탭하면 상세) / 생활 장면(임시 도형, 예정 상태 문구) / 이벤트 패널(배지·제목·화자·본문·선택지) / 조작 바(정지·배속·메뉴). 고정 높이는 dp, 장면은 남는 공간을 차지하고 이벤트 패널은 안전영역 높이에 비례(34%, 230~340dp). 소형(<640dp) 화면은 압축 모드. 메뉴: 저장 슬롯 / 가족 상세 / 가계도 / 이벤트 기록 / 콘텐츠 정보·업데이트.
