## 코어 테스트 항목 (모두 통과)
- JSON 라운드트립/오류 거부, 한글·이스케이프
- 팩 검증: 미지원 조건/효과 op → "앱 업데이트 필요", 알 수 없는 변수·역할, 계약 버전 초과, 이벤트 id 충돌, 의존 팩 누락
- 확인된 규칙: 능력치 등급 경계, 무드 단계 경계, 가중 게이트 확률(체력 1979→약 25%, 1980→약 75%, 20,000회 표본 ±2%p)
- 조건: 존재하지 않는 역할 참조 시 불충족, 한국어 조사 처리
- 이벤트 진행: 페이지 → 선택(선택 전 진행 불가) → 결과 → 효과·플래그·기록, 쿨다운/최대 횟수
- 장기 시뮬레이션 30년: 같은 시드 → 동일 결과(결정성), 다른 시드 → 다른 결과, 원작 구조 이벤트 실제 발생
- 저장: 이벤트 진행 중 저장→복원 후 난수 흐름까지 동일하게 이어짐, 4개 슬롯 독립, 주 파일 손상 시 `.bak` 복원, 마이그레이션 체인, 미래 schema 거부
- **콘텐츠 업데이트**: 새 팩 설치 후 기존 가족·기록·능력치 유지 + 새 이벤트 발생 가능 / 진행 중 이벤트가 팩 개정(이벤트 삭제)에도 스냅샷으로 완주 / 해시 불일치·검증 실패·id 충돌·같은 버전 재설치 거부 및 기존 상태 유지 / 최신 팩 손상 시 이전 버전 → 번들 순 롤백
- 화면: 11개 세로 해상도/안전영역 조합(320×568dp 소형 ~ 1440×3120, 9:16~9:21, 노치, 태블릿 세로)에서 영역이 안전영역을 빈틈·겹침 없이 채우고, 조작 바 ≥48dp, 이벤트 패널 ≥170dp, 장면 영역 최소치 확보

## 원작 캐릭터 파트 조합 검증
- 정답 데이터: 원작 '내가 아는 가족' 캐릭터 선택 목록을 에뮬레이터로 열어 색 번호 그대로 추출(`gallery.py`). 아빠·엄마·아들(18세) 각 84명 = 252명. 딸·조부모 목록은 아직 추출 안 함.
- 방법: `gallery_fit.py` 가 ROM 파트 번호만 바꿔 가며 `charcompose.py` 규칙으로 그린 결과를 정답과 픽셀 비교(위치는 규칙이 정하고, 탐색은 번호만).
- 결과(차이 픽셀 수): 아빠 0px 63 / ≤3px 71, 엄마 65 / 81, 아들 60 / 72 → **252명 중 188명 완전 일치, 224명 3px 이하**.
- 남은 차이: 안경 쓴 몇몇 캐릭터의 눈 높이 1px, 일부 목 부분(의상 묶음 차이로 추정), 탐색이 국소 최솟값에 머문 몇 건. 규칙 자체의 미해명 부분은 docs/07 "아직 모름" 참고.
- C# (`Core/CharacterParts.cs`) 테스트: 합성 데이터 규칙 테스트(항상 실행) + 로컬 원작 자료가 있으면 252명 모두 C# 차이 수 = 파이썬 차이 수 확인 (`SK_LOCAL_ART`, `SK_GALLERY_IDX` 환경변수).

## 화면 미리보기 (실제 Unity 캡처 아님)
`docs/preview/*.png`는 Unity 렌더링이 아니다. `tools/ScreenPreview`가 **실제 코어**(레이아웃 계산·세션·이벤트 텍스트)로 영역과 문구를 덤프하고 `tools/render_preview.py`가 `GameApp.cs`와 같은 배치 수식으로 그린 근사 그림이다(폰트도 나눔고딕으로 대체). 실제 Unity 화면과 글꼴·여백이 다를 수 있다.
이 미리보기로 발견해 고친 문제: ① 소형(360×568dp)·태블릿에서 선택지가 본문을 가림 → 선택지가 많으면 이벤트 패널을 장면 위로 확장, ② `⏸` 글리프 깨짐 → "정지" 글자, ③ 짧은 장면에서 인물과 캡션 겹침.
