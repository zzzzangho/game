# 07. 원작 화면 관찰 (에뮬레이터 직접 실행)

`tools/gba_capture/capture.c`(libmgba, 헤드리스)로 사용자 ROM을 실행해 확인했다. 캡처 이미지와 상태 파일은 **로컬 전용**이며 저장소에 올리지 않는다.
빌드: `gcc -O2 -DUSE_DEBUGGERS -o capture capture.c -lmgba` (Ubuntu `libmgba-dev` 0.10. `-DUSE_DEBUGGERS` 없으면 구조체 배치가 달라 크래시).

## 확인한 화면 구조
- **메인 화면**: 집의 단면도가 가로로 이어지고(방 단위, 좌우 스크롤), 가족이 방 사이를 걸어 다닌다. 큐피트가 떠다니며 선택된 인물 위에 초록 화살표.
- **상단 HUD**: `N년가족`(가족 연차) · 날짜(요일 포함, 시작 날짜는 플레이어 입력) · 시계 아이콘 · R 버튼 표시.
- **하단 인물 바**: 얼굴, 이름, 하트 3칸(부분 채움 → 하트는 연속값), `★예정 상태 문구`, 세로 게이지, `활쏘기` 버튼.
- **인물 상세**(가족보기): 꿈, 맞은 화살, 지력·체력·매력·운 등급(F~SS), 하트, 신님에게 감사(개수), 나이, 세대주 왕관, `현재` 예정 상태 제목 + 설명 + 결과 경향(예: "무드↑↓변화 하트↑↓변화").
- **도입**: 천계의 신님 → "가족을 다음 세대로!" → 시작 연월일 입력 → 가족 소개 → 플레이어(신님) 이름 입력 → 큐피트 안내 → 화살 튜토리얼(힘내라/진정해의 화살 각 5개).
- 대화창: 둥근 말풍선형, 이름 파랑·키워드 초록/빨강 강조.

## 에셋 추출 가능성 (확인됨)
mGBA 레이어 토글로 분리 가능: OBJ(캐릭터·큐피트·말풍선 아이콘)만 / BG3(방 벽) / BG2(가구) / BG1(HUD 문자) / BG0(대화창).
→ 런타임 캡처 방식으로 원작 그래픽을 추출할 수 있다. 정적 ROM 압축 포맷을 몰라도 된다. 애니메이션은 연속 프레임으로 얻는다.

## 기존 프로토타입과의 차이 (반성)
첫 버전 UI는 원작 화면을 보지 않고 만든 일반적인 구성이었다. 원작의 핵심 시각 요소(집 단면도, 큐피트, 인물 바, 화살 조작)가 빠져 있었다. 다음 버전에서 원작 구조를 따라 다시 짠다.

## 원작 그래픽 로컬 추출 (구현됨)
`python3 -I tools/gba_capture/build_local_art.py <rom.gba>` (선택: `GUIDE_LAYOUT=<guide저장소>/assets/data/family-save-layout.json`)
→ `unity/Assets/Resources/LocalArt/` (git 제외, 약 25초)
1. 고정 입력으로 타이틀 → 도입 → 튜토리얼 → 메인 화면까지 진행.
2. **스프라이트**: 매 프레임 OAM·VRAM·OBJ 팔레트를 해독해 고유 셀만 수집(약 120개). 자동 분류:
   - 캐릭터 32×64: 옷 색으로 앞·뒷모습을 한 인물로 묶고, 화살 효과 프레임(빨간 외곽선)은 제외, 머리색으로 초상화(32×32)를 연결.
   - 큐피트(노란 머리) 프레임, UI(하트 가득·반·빔, 게이지 3단, 선택 화살표, 말풍선, 외출중, 활쏘기 버튼 등)는 이 ROM의 셀 해시로 이름 매핑.
3. **집 배경**: 카메라 변수(`0x020047F0` 및 추적값 2개)를 직접 써서 세계를 한 바퀴 훑고, 위치마다 같은 상태를 다시 불러와 시간대 팔레트를 고정, 프레임 정합으로 이어 붙인다. 세계는 "아파트 세대(현관 → 방 3개 → 거실·부엌) → 바깥(하늘·이웃 건물)"이 960px 주기로 순환한다. 방 구간은 벽지 밝기로 자동 검출.
4. **원작 시작 가족**: 공략 사이트의 세이브 레이아웃(`record_base`/`current_date`는 상태 내 절대 오프셋)으로 상태 파일을 읽는다. 날짜는 `연<<9 | 월<<5 | 일`이다(카즈유키 1956-06-03 → 2005-01-01에 48세, 원작 화면과 일치). 능력치는 원작 상세 화면의 등급(C·B·C·A)과 일치하고, 예정 상태 `(표, 순번)`은 `planned-states.json`의 `save_refs`로 ID와 제목에 연결된다(4명 모두 원작 화면 문구와 일치).

## 새 화면 구성 (사용자 결정 반영)
HUD(N년가족·날짜·요일) / 원작 집 단면도(드래그 스크롤, 선택 인물 따라가기, 큐피트·선택 화살표·생각 말풍선) / 선택 인물 바(초상화·이름·하트 3칸·★예정 상태·게이지·◀▶) / 대화창 / 하단 메뉴 **활쏘기·아이템·큐피트·관찰**. 가족(또는 초상화)을 터치하면 상세창(꿈·화살·능력 등급·하트·신님에게 감사·현재 예정 상태)이 열린다.
그래픽 교체: `LocalArt/manifest.json`과 같은 이름의 PNG(`*.png.bytes`)만 바꾸면 직접 그린 그림으로 대체된다. 추출본이 없으면 임시 도형으로 동작한다.

## 원작 가족 만들기 (직접 확인)
- 도입부에서 신님이 "내가 아는 가족을 지켜봐 주지 않겠느냐?"라고 묻는다. **[네, 알겠습니다!]**를 고르면 신님이 아는 가족으로 시작한다. 이 가족은 실행할 때마다 달라졌다(RTC 기반 무작위로 추정. 같은 입력으로 '코노' 가족과 '후타·나기사·준페이' 가족이 나옴). **[어… 잠깐만요…]**를 고르면 "그대가 아는 가족"을 직접 만든다.
- 직접 만들기 순서: 시작 연월일 → 가족 성 → **가족 구성**(할아버지·할머니·아버지·어머니·아들/딸 4칸 중 선택) → 구성원마다 이름·성별·생일·혈액형(A/B/O/AB/?)·성격(내향적/보통/외향적)·능력 순위(지력·체력·매력·운을 1~4번으로)·직업(목록) → **캐릭터 선택**.
- **캐릭터 선택**: ① 체형 [얇은/보통/굵은] ② 캐릭터(얼굴+헤어) 목록 7페이지 × 12종 ③ 색상 변경: 머리색(8종 중 선택)·피부색·의상·의상색 → [이걸로 OK!].
- 따라서 원작 캐릭터 = 체형 × 캐릭터 × 머리색 × 피부색 × 의상 × 의상색의 조합이다. 이 구조대로 원작 파트를 추출해 무작위 조합에 쓴다(진행 중).

## 원작 캐릭터 파트: ROM 직접 추출 (조합 규칙 확인됨)
- 캐릭터 스프라이트는 게임 코드가 RAM에서 32×64 한 장으로 합성한 뒤 DMA로 VRAM에 올린다(BIOS 압축 해제 없음). 재료(파트)는 ROM `0xA147A8~0xA8A300`에 **압축 없이** 들어 있다.
- **파트 형식**: 4bpp 행 비트맵(한 행 = `폭/2` 바이트, 하위 니블이 왼쪽 픽셀, 타일 배열 아님), 4바이트 정렬.
  - 헤더 8바이트 `[u16 식별값][폭][높이][기준점 x(s8)][기준점 y(s8)][추가값 2]`. 정면 얼굴만 16바이트(기준점 표가 더 붙고 +13~15 = `FF FF FF`).
  - 묶음 헤더 `10 | (n-1)<<4 | 형(1~3) | 플래그 | s8 | s32 | s32 | u32 표 끝(=16+4n) | u32 오프셋×n`. 몸통 묶음은 표 뒤에 u16 보조표가 붙어 첫 오프셋이 표 끝보다 뒤다.
  - 파서: `tools/gba_capture/romparts.py` — 965묶음. 묶음 주소를 가리키는 포인터·오프셋 표는 찾지 못했다(미해명).
- **분류**(주소 범위, 갤러리 대조로 확인): 뒷머리 208(0~103 = 정면용, 104~207 = 뒷모습으로 보임) · 얼굴형B 25(기준점 표 짧음, 쓰임 미확인) · 눈 122 · 앞머리 104 · 입 55 · 기타 4 · 코 38 · 정면 얼굴 25 · 몸통 384(24개씩 16벌 — 방향·걸음 프레임으로 추정, 정면 서기 = 48~71).
  - 묶음 안의 n개는 연령 변형으로 보인다(갤러리 성인은 모두 1번). 0/2/3번의 의미는 미확인.
  - 몸통 정면 48~59 남, 60~71 여. 갤러리는 48~51 / 60~63 만 쓴다(나머지 8개는 다른 체형으로 추정).
- **조합 규칙** (`tools/gba_capture/charcompose.py`, Unity `Core/CharacterParts.cs` 에 같은 규칙):
  - 원점 O = 발 아래 중앙. 몸통 좌상단 = (Ox−ax, Oy−16−ay), 목 = (Ox+ext0−16, Oy+ext1−32).
  - 얼굴 메타 m[0..8]: ref = 목y − m0. 얼굴 좌상단 = (목x − m7, ref + m1 − 2). 앞머리 기준점 (목x, ref+m1), 눈 ref+m3, 코 ref+m4, 입 ref+m5.
  - **앞머리 N번 ↔ 뒷머리 N번**이 한 헤어스타일. 뒷머리 기준점 y = ref + m2 + 16 − (뒷머리 ext1).
  - 순서: 뒷머리 → 몸통 → 얼굴 → 코 → 눈 → 입 → 앞머리. 눈·코·입은 좌우반전해 쓰기도 한다(반전 시 ax = 폭 − ax).
- **검증**: 원작 캐릭터 선택 갤러리 252명(아빠·엄마·아들 18세 각 84, `gallery.py` 로 색 번호 그대로 추출)을 `gallery_fit.py` 로 분해 → 결과는 `docs/04_검증결과.md` 참고.
- **색 표**(ROM, 색 선택 화면 캡처와 대조): 머리 8색(칸 3~5) `0xA436E8`부터 32바이트 간격(+1색은 `0xA436C8`), 피부 4색(칸 6~10) `0xA49900`부터 48바이트 간격(1색은 `0xA498D0`), 의상색(칸 11~14) 표 `0xA44070`, 항목 = 1 + 48×색 + 4×의상 (**추정** — 체형·성별 보정 미해명). 갤러리 프리셋은 각자 고유 색을 가진다(캡처 PNG 에서 읽음).
- 원작 스프라이트의 팔레트 칸: 1 외곽선 / 2 흰자 / 3·4·5 머리 / 6~9 피부, 10 볼터치 / 11~14 의상(윗옷 2·아랫옷 2).
- **아직 모름**: 딸·할아버지·할머니 갤러리(미추출), 연령 변형 0/2/3의 실제 쓰임, 체형 3종과 몸통 묶음의 대응, 걷기·뒷모습 프레임 배치, 원작이 "신님이 아는 가족"의 외형을 고르는 규칙.
