## 2. 규칙 확인 수준 (이 프로젝트의 분류)

**확인됨** = 공략 데이터가 ROM 정적 분석 값으로 제시하고, 구현·테스트에서 그 값을 그대로 사용한 것.
**추정** = 데이터는 있으나 해석(의미·단위·경계)에 가정이 들어간 것. **미해명** = 근거 없음, 임시 구현이거나 미구현.

| 항목 | 상태 | 비고 |
|---|---|---|
| 능력치 4종(지력·체력·매력·운) 범위 0~5000, 등급 F/D/C/B/A/S/SS 경계(0,800,…,4800) | 확인됨 | 테스트로 경계 검증 |
| 가족 무드 0~255, 5단계 경계(0/48/96/160/208) | 확인됨 | 테스트로 경계 검증 |
| 예정 상태 → 결과: 표 순서대로 검사, 처음 통과한 하나만 선택, 마지막은 폴백 | 확인됨(`first_matching…`, `order_confirmed`) | 다중 후보 경로(195개 상태)는 의미 불명확 → 미구현 |
| 가중 게이트 `(능력 < T 그리고 1/4) 또는 (능력 ≥ T 그리고 3/4)`, 2단 게이트 | 확인됨(수치) / 추정(복원 방식) | 2단 게이트는 `chance_percent`가 누적 확률이라 개별 확률로 역산했다 |
| 이벤트 효과의 "기본값"(하트 ±N, 능력치 ±N, 숙련도, 무드, 자산) | 확인됨(기본값) | **"몰입도·상태 보정" 계산식 미해명** → 보정 없이 기본값만 적용 |
| 아이템(고리: 등급 한 단계 +800 상한 5000, 행복 상자 등), 화살 효과 | 확인됨(일부) | 이번 버전 미구현 |
| 시간 진행 단위·달력 | **미해명** | 임시: 1년=12×30일, 하루 1틱 |
| 이벤트 발생 빈도, 예정 상태 배정 방식·지연 일수 | **미해명** | 임시(가중 무작위 / 20~60일) |
| 연령 분류 경계(유아·아동·초등·중등·청년·젊은이·중년·노년) | 추정 | `유아: 1~3세`만 명시. 나머지는 임시 경계 |
| 하트의 단위·최대값 | **미해명** | 임시 0~1000. 효과값(±24/48)이 같은 단위라는 가정 |
| 결혼·출산·세대교체·사망·직업 시스템 | **미해명/미구현** | 데이터에 "관계/상태 코드" 번호만 있고 의미표 없음 |
| 난수 알고리즘 | **미해명** | 자체 xorshift 사용 |

### 데이터 사이의 불일치(그대로 옮기지 않고 기록)
1. **a5/a6 의미**: `planned-states.json`은 `person_s0_a5`=하트, `a6`=몰입도로 쓰고, `predictor-events.json`은 같은 번호를 `a5`=현재 관심 몰입도(+0x5B), `a6`=꿈 계승 보조값으로 부른다. → 이 프로젝트는 planned-states 쪽을 따랐다(미확정).
2. **+0x50~0x56**: 세이브 레이아웃·아이템 데이터는 지력/체력/매력/운인데 예측기 필드 목록은 같은 오프셋을 "애정 붐/독신 붐/마이웨이/대망 미터"로 부른다. → 능력치로 사용(미확정).
3. **임계값 표기**: `checks.threshold`=2600이지만 `probability_tree.gates.threshold`와 수식은 2340(=2600×9÷10). 트리/수식 값을 사용.
4. 직업은 코드만 있고 **이름이 없다**. 스킬 183개 중 11개는 이름이 "더미".

## 3. 그래픽·음악 조사 (`tools/rom_survey.py`, 통계만 출력)
- 표준 BIOS **LZ77(0x10) 블록이 사실상 없음**(유효 디코드 3개, 모두 512B 미만). 일반적인 GBA 에셋 압축이 아니다.
- **Sappy/m4a 엔진 시그니처 없음**(`Smsh` 리터럴 0). 표준 m4a 곡 테이블이 아니므로 음악 추출 도구를 그대로 쓸 수 없다.
- 16색 팔레트 모양 후보는 8,366곳으로 많지만 통계만으로는 구분 불가.
- 결론: **그래픽·애니메이션·음악은 자체 압축/엔진일 가능성이 크고, 추출에는 별도의 리버스 엔지니어링(디스어셈블 + 에뮬레이터 VRAM 덤프 대조)이 필요**하다. 이번 단계에서는 추출하지 않았고, 화면의 모든 그래픽은 코드로 그린 **임시 도형**이다. 원작 에셋을 쓸 경우에도 권리 문제(05번 문서)가 먼저 해결되어야 한다.

## 4. 개발 환경 확인
- Unity 에디터: 공식 API로 `6000.3.25f1`(LTS) Linux 에디터 다운로드 경로가 보였다(약 4.5GB, 설치 8.7GB + Android 모듈). **그러나 라이선스 활성화(계정 로그인/시리얼)가 필요한데 이 환경에서는 대화형 로그인이 불가능**해 에디터를 설치·실행하지 않았다. → 에디터 실행, APK 빌드, 기기 검증은 **수행하지 못했다**(README 참고).
- 대신 `dotnet 8`을 설치해 Unity 비의존 코어를 컴파일·테스트했고, Unity 계층은 NuGet의 UnityEngine 2021.3 참조 어셈블리 대비 컴파일 오류 0건을 확인했다(타입/API 존재 확인일 뿐, 실행 검증 아님).
- 진행 중 만난 제약: 저장소 `zzzzangho/game`에는 다른 프로젝트(김전일 GBA 팬게임)가 이미 있어 충돌을 피하려고 `sennen-kazoku/` 하위에 모두 넣었다.

## 5. 기술적 난점 요약
1. 조건이 서술문/해독 불가 함수로 남은 이벤트가 많다 → 완전 모델링된 상태만 가져오는 방침(현재 918개 중 282개, 30.7%).
2. 대사 제어 토큰 의미표가 없다(인물 참조·색·대기·줄바꿈). 일부만 추정.
3. 결혼·출산·세대교체의 "관계/상태 코드" 의미 미해명 → 원작 재현 범위를 가장 크게 제한.
4. 이벤트 처리 직후 변하는 내부 게이지(MAX/MIN 이벤트 공통 게이지)의 이름과 갱신 규칙 미해명.
5. 그래픽·음악 포맷 미해명.
