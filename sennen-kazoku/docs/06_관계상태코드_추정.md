# 06. 관계/상태 코드 의미 추정

공략 데이터에는 `이벤트 발생 본인의 관계/상태 코드 N`, `인물 슬롯 15의 유효 상태`, `미정 코드 N`(대상 분류) 같은 번호만 있고 의미표가 없다.
아래는 **조건이 걸린 예정 상태/이벤트의 제목·대상 분류·연령 분포를 교차 대조해 추정**한 결과다(ROM 직접 해독 아님). 신뢰도는 근거의 일관성 기준.

| 코드 | 추정 의미 | 신뢰도 | 근거 | 구현 |
|---|---|---|---|---|
| 15 (+ 슬롯 15 유효) | 배우자 있음 | 중상 | 예측기 데이터가 "15 · 배우자 조건 충족"이라고 명시. "결혼하고 싶어/결혼에 호기심" 상태는 15 **아님**을 요구, "남편을 돕는 데…"는 15 요구. 단, 초등 여아 대상에도 15 요구 항목이 있어 의미가 정확히 "기혼"인지는 불확실 | `relation: spouse` |
| 28 | 연인(교제 상대) 있음 | 중 | "청혼하고 싶어"(대상 코드 51 계열), "데이트에 푹 빠졌어", "바람피워 주겠어"가 28 요구. "결혼하고 싶어", "같은 반 그 녀석이 짜증 나"는 28 아님 | `relation: lover` (연애 시스템이 없어 플래그 `lover`로만 표현) |
| 16 | 자녀의 배우자(며느리·사위) 있음 | 상 | "며느리를 구박/아껴", "사위를 구박/아껴"가 16 요구 | `relation: child_spouse` |
| 18 | 손주 있음 | 상 | "손주 응석 받아 주기", "손주의 신부 모습을 보고 싶어"가 18 요구 | `relation: grandchild` |
| 5, 6 | 어린 가족 구성원(자녀 쪽) 분류 | 낮음 | 유아·초등·중등 대상에 집중, "부모 흉내", "응석", "낮잠". 단 "남편의 부모님을 신경 쓰느라 녹초"(며느리)에도 6이 있어 단순 자녀 코드가 아님 | **미구현** |
| 7~10 | 자녀 단계/성별 관련 분류 | 낮음 | 동일한 11개 항목에 4개 코드가 같이 쓰임("부모 노릇의 어려움") | 미구현 |
| 20~22 | 상담 상대가 되는 다른 인물 슬롯 | 낮음 | "육아 고민 상담", "부부 관계에 조언" 이벤트 | 미구현 |
| 27 | 대학생 신분 | 중하 | "학점", "맹렬하게 출석" 이벤트에서 27 요구 | 미구현 |
| 1, 2, 3 | 세대주/소득 관련(1,2), 장난 상태(3) | 낮음 | 사례 2~3건 | 미구현 |
| `미정 코드 N` (대상 분류) | **직업 분류** 가능성 | 중하 | 코드 25·27은 영화/연구/수사/취재 같은 직업 테마, 45·41·46·48은 학령기 비행·가정 테마. 직업 이름표(코드→이름)가 데이터에 없어 확정 불가 | 해당 상태 239개 미구현 |

### 이번 반영
- 조건 언어에 `relation` 연산 추가(데이터 계약 v2), 가족 구조에서 계산(`Relations.cs`): 배우자/연인/자녀의 배우자/손주.
- 변환기가 위 4개 코드와 `인물 슬롯 15 유효 상태`, `현재 연도`, 괄호가 섞인 `또는/그리고` 조건문을 해석(우선순위: 그리고 > 또는, 괄호 우선 — 추정).
- 효과: 로컬 원작 팩 변환 수 282 → 285개 상태(708개 결과). **증가폭이 작다.** 변환을 막는 주된 장벽은 관계 코드가 아니라 ① 대상 분류의 `미정 코드`(239), ② 다중 후보 경로(195), ③ `unknown` 판정 노드(71)와 컨디션 단계 조건이다.

### 다음에 풀어야 할 것(우선순위)
1. `미정 코드` → 직업 이름표: ROM의 직업 테이블 해독(또는 세이브의 `job_raw`와 대조) 필요.
2. 다중 후보 경로 195개 상태의 선택 규칙(경로 간 우선순위) 확인.
3. 컨디션 단계(`a20`, 이벤트 조건에 2,300건 이상 등장)의 정의와 변화 규칙.
4. 결혼·출산 자체의 진행 규칙(코드 15/28이 어떻게 켜지는지)은 **이 데이터로는 알 수 없다** — 사건 시작 조건("청혼하고 싶어" → 결혼 이벤트)을 단서로 추가 조사해야 한다.
